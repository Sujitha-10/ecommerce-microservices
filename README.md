# Ecommerce Microservices Backend

A backend application built using **Spring Boot Microservices Architecture** demonstrating service discovery, API Gateway routing, JWT-based authentication, inter-service communication, and event-driven communication using Apache Kafka.

## Architecture Overview

The application follows a microservices architecture where each service is independently developed and deployed.


## Technologies Used

### Backend
- Java 21
- Spring Boot
- Spring Cloud
- Spring Data JPA / Hibernate
- Spring Security
- JWT Authentication

### Microservices Components
- Eureka Server (Service Discovery)
- API Gateway
- OpenFeign (Inter-service communication)
- Apache Kafka (Event-driven communication)

### Database

# Microservices

## 1. Eureka Server

**Port:** 8761

Responsible for service registration and discovery.

All microservices register themselves with Eureka Server to communicate dynamically.

---

## 2. API Gateway

**Port:** 8080

Acts as the single entry point for client requests.

Responsibilities:
- Routing requests to appropriate services
- Centralized request handling

---

## 3. User Service

**Port:** 8083

Handles user-related operations.

Features:
- User registration
- User login
- Password encryption using BCrypt
- JWT token generation

Database:
user_db
|
users table

---

## 4. Product Service

**Port:** 8081

Manages product information.

Features:
- Add products
- View products
- Update product quantity
- Product availability checking

Database:
product_db
|
product table

---

## 5. Order Service

**Port:** 8082

Handles order processing.

Features:
- Create orders
- Validate product availability
- Communicate with Product Service using OpenFeign
- Publish order events using Kafka

Flow:

Order Request
|
Order Service
|
Product Service
|
Kafka Event

Database:

order_db
|
orders table


---

## 6. Notification Service

**Port:** 8084

Consumes Kafka events generated by Order Service.

Features:
- Kafka consumer implementation
- Processes order-created events
- Sends notification simulation

Flow:
Order Service
|
|
Kafka Topic
(order-created)
|
|
Notification Service

# Kafka Event Flow

When an order is created:

1. Order Service saves the order.
2. Order Service publishes an event.

Example event:

```json
{
  "id": 1,
  "productId": 10,
  "quantity": 5
}
Notification Service consumes the event.

Output:

==============================
Order Received
Order ID : 1
Product ID : 10
Quantity : 5
Notification Sent Successfully
==============================

Running the Application
Step 1: Start Eureka Server

Run:

EurekaServerApplication

Access:

http://localhost:8761
Step 2: Start Kafka Broker

Start Apache Kafka broker.

Kafka is required for notification event processing.

Step 3: Start Services

Start in this order:

1. Eureka Server
2. User Service
3. Product Service
4. Order Service
5. Notification Service
6. API Gateway
